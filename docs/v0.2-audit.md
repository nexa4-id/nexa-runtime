# Nexa v0.2 Source Audit

Audit target: `nexa-runtime-v0.2.zip` stored in the repository.
Development branch: `develop/v0.3`.
Baseline branch is left unchanged.

## Source inventory

The archive contains a Rust crate with:
- `src/main.rs`: CLI dispatch for `run`, `worker-demo`, and `help`.
- `src/lexer.rs`: tokens for `fn main`, `let`, `print`, identifiers, integer literals, punctuation, and arithmetic operators.
- `src/compiler.rs`: a small Pratt-style arithmetic-expression parser and bytecode emitter.
- `src/vm.rs`: a single-threaded integer stack VM.
- `src/worker.rs`: a standard-library worker pool with per-worker queues, priorities, work stealing, panic containment, counters, and graceful drain on drop.
- `examples/hello.nx` and `benches/worker-throughput.sh`.

## Findings

### Language and compiler
- The grammar currently supports only a single `fn main()` entry point.
- Statements are limited to `let` declarations and `print(...)`.
- Expressions support integer literals, local variables, unary minus, parentheses, and `+`, `-`, `*`, `/`.
- The lexer has no member-access token or `worker`, `submit`, and `wait` keywords.
- There is no task-handle type, capture analysis, worker-block grammar, or worker-related bytecode.

### VM
- Runtime values are plain `i64`; locals are a `Vec<i64>`.
- The VM has no worker-pool ownership, task table, task handles, or wait/result/error path.
- Arithmetic uses checked operations and reports division by zero and overflow.
- Printing is directly coupled to stdout.

### Worker scheduler
- The existing pool is safe Rust and uses only `std`.
- Work is placed round-robin into per-worker queues; workers pop from their own queue and steal from the back of peer queues.
- Priority selection checks High, Normal, then Low. Sustained high-priority traffic can starve lower priorities.
- The shared injector queue is currently never populated, so it is redundant in the current implementation.
- A task panic is contained; the task receiver is disconnected, so callers get a generic channel-closed error rather than a panic payload.
- Pool shutdown wakes workers, drains pending work, and joins threads.
- The pool has no cancellation, timeout, bounded queue, or explicit typed task error API.

### CLI, examples, and tests
- CLI commands are `run`, `worker-demo`, and `help`; `run` has no `--workers` option.
- The only language example is `hello.nx`.
- Existing tests cover lexer basics, simple compilation, unknown variables, VM arithmetic/division-by-zero, and worker-pool execution, priorities, panic survival, and counters.
- There are no language-level worker integration tests.

## v0.3 implementation direction

1. Preserve the current arithmetic grammar and CLI behavior.
2. Add worker syntax and compiler validation for task handles and captures.
3. Represent task handles as a distinct runtime value and consume them exactly once in `worker.wait`.
4. Run worker blocks using captured value snapshots; return typed runtime errors for task failure and panic/disconnection.
5. Wire a configurable worker count into `nexa run`, while retaining the current default behavior.
6. Add integration tests for captures, multiple tasks, invalid/reused handles, panic/error paths, and non-worker programs.
7. Add examples, CI, and documentation after implementation is testable.

## Verification limitations

The available execution environment does not have `cargo` or `rustc` installed. Therefore no `cargo check`, `cargo test`, `cargo fmt`, `cargo clippy`, or benchmark result is claimed by this audit.

The ZIP was retrieved from the repository. Most source members were inspected; the local transfer copy of `Cargo.toml` failed its ZIP CRC check, so its original contents are not treated as verified. The crate manifest must be re-fetched or reconstructed and verified before running Rust validation.

## Scope and safety

This audit is documentation only. No files on `main` were changed, and no release or tag was created.
